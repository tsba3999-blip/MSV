# Серверная часть МСВ

Сервер на Node.js с одной зависимостью — драйвером PostgreSQL. Всё
остальное на встроенных средствах: меньше пакетов — меньше того, что
может сломаться при установке.

## Развернуть

Обычно вручную не нужно: после отправки в GitHub всё делает
`.github/workflows/deploy.yml` (см. `КАК_ВЫКЛАДЫВАТЬ.md` в корне).

Первая установка на сервер, где стояла старая версия (сделано 20.09.2026):

```bash
cd /var/www/MSV && git pull
bash server/setup-env.sh      # создаёт /opt/msv/server/.env из старого /opt/msv/.env
bash server/reset-old-db.sh   # удаляет таблицы старой версии (тестовые данные)
bash server/deploy.sh
```

Обновление вручную:

```bash
cd /var/www/MSV && git pull
bash server/deploy.sh
sudo -u postgres psql msv -f server/db/seed-uyut.sql    # реальные резиденты Уюта
sudo -u postgres psql msv -f server/db/seed-forma.sql   # реальные резиденты Формы
sudo -u postgres psql msv -f server/db/seed-staff.sql   # сотрудники
```

Первый запуск создаст `/opt/msv/server/.env` из примера и остановится:
впишите туда `DATABASE_URL` (пароль базы — в старом `/opt/msv/.env`)
и `SESSION_SECRET`, потом запустите ещё раз.

Скрипт заменяет старую службу `msv` — имя то же. Старый `app.js`
и `index.html` в `/opt/msv` больше не используются: сайт отдаётся
из `/opt/msv/web/`, которая копируется из git.

## Как устроен вход

По приглашению, без смс.

1. Модератор в кабинете нажимает «Пригласить резидента»: имя, телефон,
   четырёхзначный код → `POST /api/auth/invite`. Учётная запись создана,
   код сохранён хэшем. Код сообщается лично.
2. Резидент вводит телефон и код → `POST /api/auth/verify-pin`. Ответ
   на любую неудачу один — «код не подошёл»: нельзя понять, есть ли
   такой телефон.
3. Три промаха — блокировка на 30 минут. Для своих — по учётной записи,
   для посторонних — по телефону в `login_attempts`. Сверху — лимит
   10 попыток в минуту с одного IP.
4. При первом входе сервер возвращает `firstLogin: true` — сайт ведёт
   в анкету. Резидент может сменить код: `POST /api/auth/set-pin`.
5. Сессия — подписанная cookie на 30 дней. Внутри id и роль.

В `DEMO_MODE=1` код `7777` принимается за любой существующий контакт.

## Уведомления

`lib/notify.js`. Telegram работает через Bot API без библиотек: токен
и служебный чат — в настройках. Почта и Max — функции с готовой
сигнатурой, внутри `throw`: подключить провайдера, заменить тело.

Администрации идут: новые заявки в сервис, заявки на подключение
объектов, просрочки. Резидентам — смена статуса заявки, напоминания об
оплате, новости. Каждый вид включается отдельно в настройках. Каждая
отправка — в `notify_log` с результатом.

Как резидент подключает Telegram: жмёт ссылку
`t.me/<бот>?start=<телефон>`, бот получает `/start` с телефоном, вебхук
`/api/telegram/webhook` находит учётную запись и запоминает `chat_id`.
Вебхук нужно один раз зарегистрировать у Telegram:
`https://api.telegram.org/bot<токен>/setWebhook?url=https://ваш-домен/api/telegram/webhook`
— для этого у сайта должен быть https.

## Защита

Что сделано на сервере: лимит 300 запросов в минуту с адреса и 10
попыток входа; заголовки, запрещающие встраивать сайт в чужие страницы
и грузить скрипты с посторонних доменов; вся логика и данные — в базе,
посетителю не отдаются.

Что есть, но выключено: `web/protect.js` — запрет выделения, правой
кнопки, печати. Мешает посетителям, не мешает копирующему. Включать
флагами внутри файла, осознанно.

`build.sh` сжимает JS и CSS в `/opt/msv/web`: код становится нечитаемым
для беглого просмотра. Копированию не мешает.

**Роль берётся из учётной записи.** Кнопка на первой странице ни на
что не влияет — здесь окончательно закрывается вопрос, который мы
обсуждали в начале.

## Резервные копии

`deploy.sh` ставит таймер: каждую ночь в 03:30 запускается
`backup/backup.sh`. Он читает из таблицы `settings` два значения —
`backup_every_days` (раз в сколько дней) и `backup_keep` (сколько
хранить), делает `pg_dump` в `/opt/msv/backups/` и удаляет лишние.
По умолчанию каждую ночь, хранит три.

Менять периодичность — пока прямо в базе:

```sql
UPDATE settings SET value = '2' WHERE key = 'backup_every_days';
```

Экран настроек в кабинете администратора, где это будет крутиться
ползунком, — отдельный шаг.

Восстановить из копии:

```bash
gunzip -c /opt/msv/backups/msv-2026-09-11-0330.sql.gz | sudo -u postgres psql msv
```

## Правки содержимого

`POST /api/content` принимает правки от карандаша и складывает в
`content_overrides`. Перед сохранением HTML чистится: убираются
`<script>`, обработчики событий и ссылки `javascript:`. Модератор —
свой человек, но одной ошибки достаточно, чтобы сломать сайт всем.

## Что проверяет база, а не код

Переселение брони (`PATCH /api/bookings/:id`) не проверяет занятость
само: оно пробует записать, а база отклоняет пересечение ограничением
`EXCLUDE`. Сервер переводит код ошибки `23P01` в ответ «Место занято
на эти даты». Так правило живёт в одном месте и не расходится.

Каждое переселение и каждая правка заявки пишутся в `audit_log`
с автором и временем.

## Что проверено

24 проверки в `test/run.js` работают без базы: разбор контактов,
подпись и подделка сессий, срок сессии, ранжирование ролей,
маршрутизация, защита статики от выхода за папку, ответы 401/404
запущенного сервера.

**Не проверено:** всё, что ходит в базу. PostgreSQL здесь нет. Первый
`deploy.sh` на вашем сервере это покажет — если что-то упадёт,
присылайте вывод целиком.

## Как применить на сервере

База `msv` уже есть — её создал старый скрипт. Эти файлы не трогают
старые таблицы: все новые имена отличаются от прежних (`users` —
исключение, см. ниже).

```bash
cd /var/www/MSV
git pull
sudo -u postgres psql msv -f server/db/schema.sql
sudo -u postgres psql msv -f server/db/seed.sql
```

Проверить, что встало:

```bash
sudo -u postgres psql msv -c "SELECT title, (SELECT count(*) FROM rooms r WHERE r.residence_id = s.id) AS rooms FROM residences s;"
```

Должно показать три резиденции: 16, 16 и 3 комнаты.

## Про таблицу users

В старой базе уже есть таблица `users` с полями `password_hash`
и `role text`. Новая схема объявляет `users` через
`CREATE TABLE IF NOT EXISTS` — если старая существует, новая **не
создастся**, и колонки `pin_hash`, `pin_expires`, `is_active` не
появятся.

Два пути:

1. **Чистый старт** — старая база с тестовыми данными не нужна:
   ```bash
   sudo -u postgres psql msv -c "DROP TABLE IF EXISTS users, beds, bookings, charges, payments, tickets CASCADE;"
   ```
   и затем применить схему. Старые таблицы `beds`, `bookings`, `charges`,
   `payments`, `tickets` тоже конфликтуют по именам — снести все шесть.

2. **Сохранить старых пользователей** — написать миграцию, которая
   добавит новые колонки к старой `users`. Имеет смысл, только если
   там есть настоящие люди. Судя по тому, что мы видели, там один
   тестовый клиент и администратор.

Рекомендую первый путь.

## Что схема гарантирует сама

Часть правил заложена в базу, и код их обойти не может:

- **Две брони на одном месте не пересекаются по датам.** Ограничение
  `EXCLUDE` с интервалом `[)`: выезд в 12:00 и заезд в 14:00 одного дня —
  допустимый стык. Ровно то правило, по которому шахматка разрешает
  переселение.
- Выезд позже заезда; срок регистрации не раньше выдачи.
- Оценка здоровья от 1 до 5; текст заявки не длиннее 1000 знаков.
- У пользователя есть почта или телефон — хотя бы одно.
- Номер комнаты уникален в резиденции, метка места — в комнате.

## Как устроены деньги

Три таблицы вместо одной колонки «оплачено»:

- `charges` — начисления: аренда за месяц, депозит, пени, услуги.
  Пени — отдельная строка с `kind = 'penalty'`, а не поправка к сумме.
- `payments` — платежи: сколько и когда пришло, каким способом, номер
  операции у банка.
- `booking_balance` — представление, которое считает начислено /
  оплачено / остаток. Именно эти три числа показывают шахматка,
  «Начисления» и кабинет резидента.

Так история не теряется: видно каждое начисление и каждый платёж,
а не только итог.

## Журнал действий

Таблица `audit_log` отвечает на один из пяти вопросов раздела «Права
доступа»: кто, когда и что сделал. Переселил бронь, выдал права,
начислил пени — всё пишется туда с автором и временем.

## Чего пока нет

- Почты и Max в уведомлениях — нужен провайдер.
- Загрузки документов анкеты и вложений к заявкам (фото комнат — есть).
- Оплаты через банк: сейчас оплату отмечает администратор вручную.
- Страниц резидента «История оплат», «Уведомления», «Репутация»,
  «Документы» с сервера — они ещё на демо-данных.
