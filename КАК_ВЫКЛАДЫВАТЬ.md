# Как выкладывать на сервер

Выкладка автоматическая: после каждой отправки в GitHub (ветка `main`)
GitHub сам заходит на сервер Таймвеба, обновляет там копию репозитория
в `/var/www/MSV` и запускает `server/deploy.sh`. Через пару минут
изменения видны на сайте.

Как это устроено — `.github/workflows/deploy.yml`.

## Одноразовая настройка

Нужно сделать один раз, чтобы GitHub мог заходить на сервер.

### 1. Ключ на сервере

На компьютере создан ключ `C:\Users\Professional\.ssh\msv_deploy`
(закрытая часть) и `msv_deploy.pub` (открытая часть). Открытую часть
надо добавить на сервер — в консоли сервера (панель Таймвеба → сервер →
«Консоль», или любой SSH-клиент от root) выполнить:

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAID9JpZg/l/Wi7+xlPuJw4eAkwXMXNNOmq2Yur3mb7Xm8 msv-deploy-github' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 2. Три секрета в GitHub

GitHub → репозиторий `MSV` → **Settings** → **Secrets and variables** →
**Actions** → **New repository secret**. Создать три:

| Name | Secret (значение) |
|---|---|
| `SSH_HOST` | IP-адрес сервера из панели Таймвеба |
| `SSH_USER` | `root` |
| `SSH_KEY`  | содержимое файла `C:\Users\Professional\.ssh\msv_deploy` целиком — открыть Блокнотом, Ctrl+A, Ctrl+C, вставить как есть, включая строки `-----BEGIN` и `-----END` |

Закрытый ключ (`msv_deploy` без `.pub`) никому не показывать и никуда,
кроме этого секрета, не вставлять.

### 3. Первый запуск

После настройки: GitHub → вкладка **Actions** → «Выкладка на сервер» →
**Run workflow**. Зелёная галочка — всё прошло. Красный крест — открыть
запуск, в логе будет причина.

При самом первом запуске `deploy.sh` может остановиться с сообщением
«Создан /opt/msv/server/.env из примера» — это нормально: надо один раз
вписать на сервере в `/opt/msv/server/.env` строки `DATABASE_URL` и
`SESSION_SECRET` (см. `server/README.md`) и запустить выкладку снова.
